请根据今天的实际工作内容，生成一份“当日项目总结文件”，并输出为适合保存到工程目录 `docs/daily-log/` 下的 Markdown 文档内容。

要求：

1. 文件定位为“项目日报 / 当日推进总结”，不是聊天记录，也不是流水账日记；
2. 内容要简洁、清晰、可复用，方便后续我和其他智能体快速了解当天项目推进情况；
3. 只记录对项目推进有价值的信息，不要写无关情绪或过多过程噪音；
4. 输出内容必须使用此固定结构：YYYY-MM-DD 项目日报

## 今日目标

- 写当天原计划要完成的事项

## 实际完成内容

- 写当天真正完成的结果，按阶段或模块整理

## 完成度

- 写整体完成度
- 如有必要，可拆分子项完成度

## 关键问题 / 难点

- 只写真正影响推进的问题

## 解决状态

- 对每个问题写明：已解决 / 未解决 / 部分解决
- 简要说明解决办法或当前判断

## 当前项目状态

- 用阶段状态方式总结当前项目推进到哪里
- 例如：
  - record\_upload：已完成
  - stt：已完成
  - llm：未开始

## 明日计划

- 写下一步最合理的推进事项
- 不要发散太多，只写最优先的内容

## 备注 / 关键结论

- 写当天已经确认的重要结论，避免后续重复讨论

补充要求：

1. 输出结果要适合直接保存为 `docs/daily-log/YYYY-MM-DD.md`
2. 表达风格偏工程化，不要太口语化
3. 以“阶段成果、问题定位、推进状态”为主，不要写成纯流水账
4. 如果今天某些问题已经明确不是功能问题，而只是显示层/环境层问题，要在“关键结论”里写清楚
5. 如果今天涉及接口规范，请检查描述是否与 `docs/internal-api-spec.md` 保持一致

1. 先判断项目当前做到哪一步；
2. 告诉我今天最该做什么，不要发散；
3. 按角色拆分今天任务；
4. 每项任务写清楚对应文件、目标、产出和验收标准；
5. 计划必须和 docs/internal-api-spec.md 保持一致；
6. 最后补一句：如果今天提前做完，下一步该接什么。
