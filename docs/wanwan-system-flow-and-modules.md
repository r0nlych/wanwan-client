# wanwan-client 系统流程与模块定义

## 1. 文档目的

本文档用于整合 wanwan-client 当前已确认的系统流程图和模块定义表，作为项目内长期参考文档。\
目标是统一以下内容：

- 当前开发优先链路与完整运行链路
- 用户输入、信息传输、系统结果之间的关系
- 运行模块与配置模块的划分
- 各模块的作用、输入、输出边界

本文档面向：

- 项目规划
- 任务拆解
- AI 协作开发
- 模块边界校验
- 后续代码实现对照

***

## 2. 当前系统流程总览

当前系统按三大区域理解：

### 2.1 用户输入

用户输入分为四类：

1. **文本输入**
   - 用户直接输入文本内容
   - 用于当前 MVP 阶段的最小链路验证
2. **语音输入**
   - 用户通过麦克风输入语音内容
   - 用于后续录音 / STT 接入阶段
3. **设置输入**
   - 用户填写或修改服务接入信息与运行参数
   - 进入设置链路
4. **角色卡输入**
   - 用户创建、编辑或选择角色卡内容
   - 进入角色卡链路

***

### 2.2 信息传输

#### 2.2.1 当前开发优先链路

设置接入\
→ 文本链路跑通\
→ TTS\
→ 语音输出\
→ 录音\
→ STT 回填\
→ 会话保存

说明：

- 这是当前 MVP 阶段的开发顺序
- 它表示先做什么、后做什么
- 不等于最终完整运行链路

#### 2.2.2 完整语音运行链路

语音输入\
→ STT\
→ LLM\
→ TTS\
→ RVC\
→ 语音输出

说明：

- 这是产品完整运行时的目标链路
- STT 负责将语音转成文本
- LLM 负责生成回复文本
- TTS 负责将回复文本转成基础语音
- RVC 负责对基础语音做角色化音色转换或增强
- 最终进入语音输出
- 当前阶段 RVC 属于可选增强链路，不作为 MVP 当前阻塞项；未启用时允许跳过

#### 2.2.3 当前文本最小链路

文本输入\
→ LLM\
→ TTS\
→ 语音输出

说明：

- 这是当前 MVP 阶段最先需要打通的最小业务链路
- 它用于验证设置接入、运行时配置、LLM、TTS、播放的基本协作

#### 2.2.4 会话保存支路

LLM\
→ 会话内容保存到本地

说明：

- LLM 生成的回复文本会进入会话内容保存
- 会话保存与主链路并行存在
- 会话保存用于：
  - 上下文续接
  - 历史查看
  - 后续会话读取

#### 2.2.5 设置链路

设置输入\
→ 设置保存\
→ 设置应用

说明：

- 设置链路不属于一次对话中的实时语音处理
- 它负责把用户填写的设置保存并作用到主链路

#### 2.2.6 角色卡链路

角色卡输入\
→ 角色卡保存\
→ 角色卡应用

说明：

- 角色卡链路不直接参与音频处理
- 它负责将角色卡内容保存并作用到当前会话和回复生成过程

***

### 2.3 系统结果

当前系统结果包括四类：

1. **语音输出**
   - 主链路最终结果
   - 用户可直接听到
2. **会话内容保存到本地**
   - 用于上下文续接和历史查看
3. **设置应用**
   - 表示当前设置已加载并生效
4. **角色卡应用**
   - 表示当前角色卡已加载并生效

***

## 3. 当前流程图文字化定义

### 3.1 当前开发优先链路

- 设置接入 → 文本链路跑通 → TTS → 语音输出 → 录音 → STT 回填 → 会话保存

### 3.2 完整语音运行链路

- 语音输入 → STT → LLM → TTS → RVC → 语音输出

### 3.3 当前文本最小链路

- 文本输入 → LLM → TTS → 语音输出

### 3.4 会话保存支路

- LLM → 会话内容保存到本地

### 3.5 设置链路

- 设置输入 → 设置保存 → 设置应用

### 3.6 角色卡链路

- 角色卡输入 → 角色卡保存 → 角色卡应用

***

## 4. 模块分组

当前模块分为两组：

### 4.1 运行模块

运行模块指一次对话或一次处理过程中会直接参与的模块：

- 文本输入
- 语音输入
- 语音输出
- 会话内容保存
- STT
- LLM
- TTS
- RVC

### 4.2 配置模块

配置模块指不属于每轮实时处理，而是提前配置、保存并在运行时被加载使用的模块：

- 角色卡输入
- 设置输入
- 设置保存
- 角色卡保存
- 设置应用
- 角色卡应用

***

## 5. 模块定义表

| 分组   | 模块     | 作用                                   | 输入                | 输出         |
| :--- | :----- | :----------------------------------- | :---------------- | :--------- |
| 运行模块 | 文本输入   | 接收用户直接输入的文本内容，并交给后续文本链路处理            | 用户文本              | 用户文本       |
| 运行模块 | 语音输入   | 接收用户通过麦克风产生的语音内容，并将原始语音交给后续识别模块处理    | 用户语音              | 原始语音数据     |
| 运行模块 | 语音输出   | 将最终语音结果播放给用户                         | 最终语音数据            | 用户可听到的语音结果 |
| 运行模块 | 会话内容保存 | 将当前会话中的用户内容与模型回复内容保存到本地，用于上下文续接和历史查看 | 用户文本；回复文本         | 已保存的会话内容   |
| 运行模块 | STT    | 将用户语音识别为可供后续文本处理的文字内容                | 原始语音数据            | 用户文本       |
| 运行模块 | LLM    | 接收文本内容和当前角色设定，生成回复文本                 | 用户文本；角色卡内容；历史会话内容 | 回复文本       |
| 运行模块 | TTS    | 将 LLM 生成的回复文本转换为基础语音内容               | 回复文本；当前语音设置       | 基础语音数据     |
| 运行模块 | RVC    | 对 TTS 生成的基础语音进行角色化音色转换或增强处理          | 基础语音数据；当前 RVC 设置  | 最终语音数据     |
| 配置模块 | 角色卡输入  | 接收用户创建、编辑或选择的角色卡内容                   | 用户填写或选择的角色卡内容     | 角色卡内容      |
| 配置模块 | 设置输入   | 接收用户在界面中填写或修改的服务接入信息与运行参数            | 用户填写的设置内容         | 设置内容       |
| 配置模块 | 设置保存   | 将用户填写的设置内容保存到本地，供后续加载和应用             | 设置内容              | 已保存的设置内容   |
| 配置模块 | 角色卡保存  | 将用户创建或编辑的角色卡内容保存到本地，供后续选择和应用         | 角色卡内容             | 已保存的角色卡内容  |
| 配置模块 | 设置应用   | 将已保存或当前选中的设置加载并作用到整条链路               | 已保存的设置内容          | 当前生效的设置    |
| 配置模块 | 角色卡应用  | 将已保存或当前选中的角色卡加载并作用到当前会话与回复生成过程       | 已保存的角色卡内容         | 当前生效的角色卡   |

## 6. 当前设计边界说明

### 6.1 当前重点

当前阶段重点不是复杂平台能力，而是先把以下链路跑通：

- 设置接入
- 文本链路跑通
- TTS
- 语音输出
- 录音
- STT 回填
- 会话保存

### 6.2 当前已明确的支撑能力

当前设计已经明确以下支撑能力存在：

- 设置输入 / 保存 / 应用
- 角色卡输入 / 保存 / 应用
- 会话内容保存到本地
- 文本输入作为 MVP 最小业务入口

### 6.3 当前不优先处理

以下能力当前不作为优先实现目标：

- 实时双工语音
- 流式 RVC
- 复杂聊天窗口
- 复杂状态机
- 大规模跨平台重构
- 无边界扩需求

## 8. 模块与内部阶段映射说明

本文档主要描述的是**业务模块视角**；  
`docs/internal-api-spec.md`、`docs/internal-api-payloads.md`、`docs/internal-api-compat.md` 描述的是**内部阶段协议视角**。

二者相关，但不完全等同，后续实现时应避免混用。

### 8.1 映射原则

- 业务模块用于描述“系统里有哪些能力、它们如何协作”
- 内部阶段用于描述“链路执行时，阶段结果对象如何统一表达”
- 不是所有业务模块都必须强制映射成主阶段协议
- 配置模块、存储模块默认优先按模块职责实现，不强制纳入主阶段协议

### 8.2 当前推荐映射关系

| 业务模块 | 内部阶段 / 协议位置 | 说明 |
| :--- | :--- | :--- |
| 文本输入 | 不强制对应固定阶段名 | 当前属于 MVP 业务入口，后续通常作为 `llm` 阶段输入来源之一 |
| 语音输入 | `record_upload` 或本地录音接入层 | 若走文件接入或录音文件落地，可映射为 `record_upload`；若走本地采集，也可先经过桌面输入层再进入后续阶段 |
| STT | `stt` | 对应内部阶段 `stt` |
| LLM | `llm` | 对应内部阶段 `llm` |
| TTS | `tts` | 对应内部阶段 `tts` |
| RVC | `rvc` | 对应内部阶段 `rvc`；当前允许跳过 |
| 语音输出 | `playback` | 对应内部阶段 `playback` |
| 会话内容保存 | 不属于当前主阶段之一 | 当前更适合作为存储模块 / 支路能力处理 |
| 设置输入 | 不属于当前主阶段之一 | 当前属于配置模块 |
| 设置保存 | 不属于当前主阶段之一 | 当前属于配置模块 / 本地持久化能力 |
| 设置应用 | 不属于当前主阶段之一 | 当前属于配置模块 / 运行时配置生效能力 |
| 角色卡输入 | 不属于当前主阶段之一 | 当前属于配置模块 |
| 角色卡保存 | 不属于当前主阶段之一 | 当前属于配置模块 / 本地持久化能力 |
| 角色卡应用 | 不属于当前主阶段之一 | 当前属于配置模块 / 运行时上下文能力 |

### 8.3 当前实现建议

- 主链路协议优先覆盖：`record_upload`、`stt`、`llm`、`tts`、`rvc`、`playback`
- 设置、角色卡、会话保存当前优先按模块职责收口，不要求先强行做成主阶段协议
- 若后续确实需要把设置或存储动作纳入统一阶段结构，应先更新接口文档，再更新实现

如后续产品边界发生变化，应先更新本文档，再更新代码实现。
