### 录音逻辑实现

1. **状态管理**：
   - 新增 `mediaRecorder`、`audioChunks`、`stream` 变量
   - 维护 `isRecording` 状态

2. **开始录音**：
   - 调用 `navigator.mediaDevices.getUserMedia({ audio: true })` 获取麦克风权限
   - 成功后创建 `MediaRecorder` 实例
   - 监听 `ondataavailable` 事件收集音频数据
   - 监听 `onstop` 事件处理录音完成

3. **停止录音**：
   - 调用 `mediaRecorder.stop()` 停止录音
   - 停止媒体流 `stream.getTracks().forEach(track => track.stop())`
   - 生成 `Blob` 并在控制台输出信息

4. **错误处理**：
   - 捕获麦克风权限错误，显示"无法访问麦克风"

### HTML 不是"执行"的，而是"描述"的

HTML 不是编程语言，它是**标记语言**。区别在于：

| 类型 | 做什么 |
|------|--------|
| 编程语言（如 JavaScript、Python） | 有逻辑，会**执行** |
| 标记语言（如 HTML） | 只是**描述**页面结构 |

---

### 浏览器怎么读 HTML？

```
浏览器从上到下读取 HTML 文件
        │
        ▼
遇到 <head> → 读取设置信息（标题、样式等）
        │
        ▼
遇到 <body> → 开始显示页面内容
        │
        ▼
遇到 <div class="toolbar"> → 创建工具栏元素
        │
        ▼
遇到 <script> → 执行 JavaScript
```

**浏览器不是"从上往下执行"**，而是"从上往下读取，然后创建页面"。

---

### 打个比方

盖房子：

| HTML 做什么 | 盖房子类比 |
|-------------|-----------|
| 定义 `<head>` | 画图纸，说明"这房子有什么材料" |
| 定义 `<body>` | 开始砌墙 |
| 定义 `<div class="toolbar">` | 在墙上留一个放工具的位置 |

图纸上先画材料清单，后画工具栏位置——不会报错，因为图纸只是说明，不是施工顺序。

---

### 所以不会报错的原因

1. **HTML 是描述，不是命令**——它只说"页面上有哪些东西"
2. **浏览器一次性读完整个文件**，然后统一创建页面
3. `<style>` 里定义的 `.toolbar` 是一个"规则"，告诉浏览器"所有 class=toolbar 的元素长这样"，不是立刻去找这个元素
4. 真正的元素（`<div class="toolbar">`）出现在后面，但规则已经提前定义好了，等元素出现时直接应用即可

### 打个比方

```javascript

```

```
我们写的代码                    浏览器内部的代码

getUserMedia()      ──────►   打开麦克风
                     │        检测噪音

                     │        打包成数据
                     ◄──────── 返回给我们
```

**我们只写了一行，但浏览器做了几百行甚至几千行的工作。**

---

### 这种写法叫"调用 API"

| 术语 | 含义 |
|------|------|
| API | "别人写好的功能，我们直接调用" |
| 浏览器 API | 浏览器自带的功能，比如录音、获取位置、存储数据 |
| 调用 | 像个开关，按一下，浏览器帮我们执行一大段逻辑 |

---

### 哪些是我们调的"别人写好的功能"？

| 我们写的代码 | 实际干了什么（浏览器内部的代码） |
|--------------|--------------------------------|
| `getUserMedia()` | 打开麦克风、采集音频、处理音频流 |
| `new MediaRecorder()` | 创建录音器、管理音频编码 |
| `mediaRecorder.start()` | 开始采集音频数据 |
| `mediaRecorder.stop()` | 停止采集，触发 onstop 事件 |
| `new Blob()` | 把多个数据块合并成一个文件 |
| `console.log()` | 把信息输出到控制台 |

---

### 为什么这样设计？

1. **不用从零写录音功能**：如果所有代码都要自己写，可能要几千行
2. **浏览器已经处理了兼容性问题**：不同电脑、不同浏览器，用的都是同一套接口
3. **我们可以专注于业务逻辑**：只管"什么时候开始录、什么时候停止"，录音细节交给浏览器

---

### 总结

| 问题 | 答案 |
|------|------|
| 这门语言高级吗？ | JavaScript 本身是基础语言，不高级 |
| 为什么感觉逻辑没写完？ | 逻辑在浏览器里，我们只是调用 |
| 这正常吗？ | 非常正常，所有前端开发都是这样 |
| 需要学这些 API 吗？ | 需要知道"这个函数能做什么"，不用知道它内部怎么实现 |
